# Hibiki — Progress

- **2026-10-26 · v0.1.0** — Repository created (public). ADR-0001 (Proposed), node-to-node trust and spam event model (Proposed, no new kinds), roadmap P0–P6, static preview page (no scripts, zero third-party requests, strict CSP) and owner-run installer registering the `hibiki` launcher card. Name chosen by the owner: Hibiki (響, resonance).
- **2026-10-26 · docs (no app-byte change)** — Added GPL-3.0-or-later licence. Revision 2 of ADR-0001 and the event model after review: mutual owner↔service binding, peer-score prior so the per-peer cap actually works, no score laundering, restrained negative claims, node-side peer list (the node can't decrypt the owner's 10040), quorum eligibility instead of verdict-similarity collusion checks, explicit P4 relay write-rule dependency, media/avatar IP-leak handling, bounded client ranking, NIP-44 signer fallback, single-owner scope.
- **2026-10-26 · docs** — Replaced click-to-load media with a P1 same-origin image proxy after owner feedback: images auto-load as node-made thumbnails, third-party hosts only see the VPS, and video alone is tap-to-play.
- **2026-10-26 · docs** — ADR-0001 revision 3: Applesauce v7 as the Nostr client layer (relay pool, outbox, social graph, NIP-85/10040 helpers, sqlite store; napplet excluded; pinned with a size budget). FIPS becomes the default node-to-node path with automatic `wss://` fallback.
- **2026-10-26 · docs** — Handoff now records the Applesauce and FIPS decisions.
- **2026-10-27 · docs** — UX mockups v1–v4 (onboarding, desktop glass light/dark, all sections, notes with right panel). Owner direction: content first, originals only, subtle but beautiful algorithm controls.
- **2026-10-27 · v0.2.0** — First working feed. ADR-0001 revision 4 and the event model Accepted. Feed service `hibiki-feed` (Node 22.13+, Applesauce v7 relay pool and `applesauce-sqlite` on built-in `node:sqlite`, sharp) reads the shared Suite relay first, then follows' NIP-65 outbox relays; ranks public features; serves signed image, media and link-preview proxies; relays owner-signed writes only. Trusted shell (NIP-07 + NIP-98 sign-in, confirm-and-sign) and an opaque-origin sandboxed napplet with all sections, glint explanations, signal presets and sliders, right panel and onboarding. Installer adds the service user, env file, sandboxed systemd unit, CSP headers and health-check rollback. Tests: 14 service tests (NIP-10, SSRF, signing, NIP-98, publish gate, outbox, ranking, OG, end-to-end HTTP) and 20 repo checks. Dry-run install verified in a sandbox with nginx: headers, sign-in and rollback.
- **2026-10-27 · v0.2.1** — First VPS install of v0.2.0 rolled back cleanly: the VPS CPU lacks x86-64-v2, so sharp's prebuilt binaries (and its WebAssembly fallback, which needs SIMD) cannot load. Image re-encoding now falls back from sharp to the distro's libvips CLI (stdin/stdout, untrusted loaders blocked), then to serving originals with EXIF/XMP/text metadata stripped in JS. The installer probes sharp and installs `libvips-tools` when needed; `/api/health` reports the backend. 5 new tests.
